# 天气表面仿真 · 特效交接

入口是同目录的 `handoff.json`。读取 `scenario` 确认天气、初态、温度来源和主体动静。用 `regions[]` 定位各区块的语义、材质假设、局部修正和终态均值。局部修正优先于基础材质。先打开 `preview.jpg` 对照原图、雨水响应（蓝色）和积雪终态（白色），蓝色仅供检查。

## 采样与合成

- 所有路径相对交接包。原点为应用 EXIF 旋转后的左上角，x 向右，y 向下。原图尺寸见 `size`。`region_map` 是原尺寸的整数 ID 图，以原值读取。其余图层均为 `analysis_size`。通过同一归一化 UV 采样。先用原尺寸 ID 裁剪，跨区块边缘使用最近邻或只对同 ID 的样本插值。背景组内的植被、护栏等仍应分别处理。
- `maps.depth` 从远黑到近白，为相对逆深度。将空中粒子与同尺度的场景深度比较，让前景挡住后方粒子。粒子抵达可见表面后停止原轨迹；碰撞、涟漪和挂水使用各自的局部通道。单张深度图仅含最前方可见表面。
- 用 maps.material 的原始整数索引 material_codes，获得局部修正后的材质。
- `up / exposure / support` 分别表示朝上程度、直达降水比例和留雪能力，亮度除以 255。`contact / deposition` 分别为本场直接雨水接触量和有效新雪沉积量。contact 和 ripple 另乘 `contact_scale`。这些结果已经包含遮挡和接触条件，直接采样即可。空气中的雪花密度可用 visual_gain；留雪量已按雪档固定。
- `keyframes` 给出 0、300、600 秒。每个状态图以 PNG 灰度除以 255 再乘该通道的 `state_scales` 还原。单位为相对水当量。相邻帧可插值；循环播放飘雨、飘雪时保持目标时刻的表面状态，避免桌面每轮重复长雪或跳回干燥。
- `snow` 驱动局部雪层厚薄、纹理遮盖和边缘渐变。`absorbed` 记录已吸收水量，可驱动木材、土壤等表面的湿色；`film` 驱动表面水膜和粗糙度变化，反射使用照片中合理的光源。`runoff` 是最近一个 25 秒步长的区内流出量，按 `direction_codes` 解释 `maps.direction` 的**原始整数**。只在有流量的像素沿流向延展水痕。
- `drip / landing` 是最近一步经复核出口移出的水量和落点接到的水量。按 `review.drains` 配对，各自多边形均与对应 ID 取交集。出口处出生水滴，落点处结束并反馈；有中间前景时按深度遮挡。直接雨点的水面波纹由 `ripple` 驱动，滴入水面的波纹另取水面上的 landing。
- `balance` 以整个分析网格的相对量计，初始存量 + 接收量 ≈ 末态存量 + 吸收量 + 汇入水体量。接收量只统计模型接住的水与雪。三帧是关键状态采样，实时水滴尺寸、折射与飞溅细节由渲染端设计。

## 验收

挑选一个接触面、一处遮挡边界和一个零响应区域，分别在三个时刻叠加检查。确认桌面上的雪跟随桌面透视，立面服从自己的朝向，桌沿滴水有对应出口和落点；旧雪遇暖雨时雪量下降，同时出现融水。没有出口证据的区域仅呈现区内响应。将低可信的反光、透明表面及遮挡边缘与原图对照，以复核文件记录调整。
